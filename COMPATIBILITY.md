# Compatibility and test record

## 0.15.5 audio streaming batch

Native file playback decodes and resamples on Rust workers with a one-second queue. Tests cover 22.05/44.1/48/96 kHz WAV sources, stereo isolation, seek duration, queue bounds, cancellation, underrun recovery, sample-position pause, output muting, ducking and meter reset. The callback does not acquire PCM/source/capture mutexes. Browser tests cover native file commands, output routes, mixer persistence and responsive layout. The new physical sound and grip feel have not been checked by the user yet; macOS/Linux audio hardware remains unverified. Supported compressed formats use Symphonia; they have not all been physically tested in this app.

## 0.15.3 reliability batch

Automated checks cover music pause/resume, seeking while paused, stopping during an in-flight audio append, stale transport acknowledgements, shortcut modifiers/common chords, permission-state UI and per-controller calibration isolation. Ten tabs are checked at five window widths. The single-instance plugin runs before GUI setup/core creation. macOS permission grants, native shortcut interception and physical audio still require platform/hardware validation; browser mocks do not establish those behaviors.

Existing UI, profile, macro, and platform visibility checks also pass. This pass changes presentation; it does not establish new controller or game compatibility.

## 0.16.1 tactile authoring

Adds an eight-second trigger/stereo-grip timeline, native encoded previews, per-controller personal grip/trigger limits, reusable clip metadata and game-action snapshots, and native bass/impact/texture/full-soundtrack conversion with matched-window A/B audition. Stereo clips/conversion require USB; trigger-only schedules also use Bluetooth HID. Scheduling is software based and can arrive later under load. Personal limits affect this app's output, persist locally and survive Reset; they are not controller firmware calibration. See [tactile authoring](docs/tactile-authoring.md) for workflow, limits and physical-validation status.
