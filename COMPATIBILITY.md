# Compatibility and test record

Last checked: 25 October 2026 on Windows 11. This page records observed results rather than expected support. A protocol unit test verifies report construction; it cannot prove that a particular controller firmware or game accepts an effect.

| Setup | Input | Triggers and lightbar | Haptic audio | Game bridge |
| --- | --- | --- | --- | --- |
| Standard DualSense, USB (`054C:0CE6`) | Live checks: 231–237 reports/s, zero observed sequence gaps or rejected reports; user confirmed both sticks, touch, and triggers on the live map | User saw fixed lightbar color and felt low trigger resistance; experimental Bow reports were accepted, and Reset sent a neutral report | Windows opened the four-channel endpoint and requested PCM frames; user felt a haptic preview, but intensity and latency were not measured | Synthetic Forza Dash and local JSON packets decoded and produced UI telemetry |
| Standard DualSense, Bluetooth | Full and short input layouts have unit tests; no live Bluetooth pad was available for this record | `0x31` output framing and CRC have unit tests; no live write check | Motor rumble is the app fallback. | DualSense Edge (`054C:0DF2`) | Edge button bits and identity have unit tests; no Edge hardware check | Firmware-dependent output behavior needs a physical Edge check | No Edge endpoint check | No live game check |

The optional XInput bridge needs an installed ViGEmBus driver. Its command path builds, but a three-game playability check has not been completed. Forza Motorsport 2023 and Horizon 4/5 packet layouts have synthetic decoder tests; no live racing session was used for this record.

Version 0.8.0 adds local telemetry rules, an explicit USB speaker chirp, and two-finger circle scrolling. On 21 October 2026, unit tests confirmed that a chirp writes only to the first two PCM channels at a bounded level, while regular grip output leaves them silent. The circle gesture test checks angular wrap, sudden touch-ID changes, and a rotation sample. The controller-free core smoke test confirmed that valid UDP telemetry can drive a scripted light and cue, that a runaway rule stops, and that the core stays alive afterward. The Playwright UI test covered the editor and speaker control. No pad was connected for this release's live smoke run, so the speaker chirp has not been audibly checked and the new paths have not been exercised on hardware.

Version 0.9.0 adds opt-in primary-display color sampling and a color mode based on the uncalibrated controller sensor estimate. A live desktop test read pixels through Windows GDI and received a sample from the background worker. Unit tests checked the color mix, smoothing, and sensor-color scale. Playwright covered the Lightbar controls and status. No controller was attached to measure the actual lightbar output or USB/Bluetooth update timing.

Version 0.10.0 renames the desktop app to CONTROLLER and copies valid profiles from the old Aftertouch data folder on first load. The migration test confirms the original archive remains intact. Cargo check, strict Clippy, Rust tests, the browser UI smoke test, and a controller-free core telemetry/script smoke test passed. The HID probe found no attached pad for this run, so live USB and Bluetooth writes, physical trigger force, and haptic output were not retested.

Version 0.11.0 adds signed Windows installer updates and a controller-free test lap for the Local JSON telemetry adapter. The release build produced an NSIS installer and updater signature; the generated `latest.json` points to that signed artifact. Rust tests, strict Clippy, Playwright UI smoke, and the controller-free core telemetry/script smoke passed. The signed GitHub release was published on 22 October 2026. An installed-app update has not been observed end to end.

On 24 October 2026, a standard DualSense (`054C:0CE6`) was connected over USB. The HID probe opened it and parsed a 64-byte input report. The rebuilt portable executable's core smoke check read 237 reports/s with zero observed sequence gaps or rejected reports, and accepted low-force trigger and reset commands. The expanded feature smoke check exercised manual, battery, screen, and sensor lightbar modes; the screen sampler emitted a color and the controller reported raw sensor bytes between `1` and `7` across runs. The four-channel USB audio endpoint opened, delivered PCM callbacks, and accepted the speaker chirp command. A silent system-audio bridge opened, a haptic preview used the voice-coil route, input click and alerts armed and cleared, and synthetic Forza and local JSON telemetry arrived. These checks confirm report and stream handling; they cannot establish visible LED color, physical trigger force, audible chirp, or perceived haptic strength without human observation. The raw sensor byte has no verified temperature unit, so the app now displays it without a °C label or battery-health estimate. The [Linux DualSense report layout](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-playstation.c) labels this byte `reserved2`.

Version 0.11.1 extends the USB integration check to full input fields, touch mode commands, motor rumble, lightbar ownership, and Reset while effects are armed. A live run exposed a WASAPI buffer discontinuity that stopped the audio bridge even though CPAL kept streaming. The bridge now counts these recoverable glitches and continues; the packaged build's live checks passed at 234 reports/s with zero gaps or rejected reports, and a two-second loopback probe passed. The updater now reports the actual installed version when no update is available, Diagnostics can copy a path-free summary, and release CI includes the browser UI smoke test. Physical feedback, live games, Bluetooth, Edge, and an installed-app update still require separate observation or hardware.

On 25 October 2026, the user checked a standard DualSense over USB. The front controller map mirrored both sticks and L2/R2, right-stick motion appeared in Activity, and Game mode did not navigate the app. The user confirmed touchpad pointer and two-finger scroll, trigger clicks, and a D-pad shortcut in PC control with another window focused. Fixed lightbar color, low trigger resistance, and haptic previews produced physical output, though their feel and accuracy still needed tuning. The first timed calibration failed to save in a hands-on attempt. Version 0.11.2 replaces it with an untimed, user-advanced guide and live measured ranges; hardware confirmation of that revised save path is recorded separately after retest. The 0.11.2 portable build's USB core smoke check read 235 reports/s with zero gaps or rejected reports. Its feature check exercised light modes, 31 USB PCM callbacks, trigger/click commands, and synthetic Forza and local JSON telemetry. Browser UI tests cover the complete guide and its save command, but cannot establish the physical accuracy of the controller sensors.

The later 0.11.2 build adds right-stick desktop scrolling, trigger report-byte and touchpad-corner calibration visuals, independent ten-zone L2/R2 graphs, separate white player-indicator controls, and editable Overwatch 2 hero templates. Protocol tests verify the player-indicator report bytes and zone encoding; Playwright covers the controls and template creation. A signed NSIS installer was built with the optional signed ViGEmBus setup and an embedded WebView2 bootstrapper. The user confirmed that the separate physical white player lights and RGB lightbar worked and the untimed calibration saved. Right-stick scrolling felt jerky or delayed. The controller's trigger report is eight bits per trigger, so further lever movement after the byte reaches 255 cannot be recovered through this input report. The hero templates are static: no live Overwatch ability, impact, or hero-selection event feed was available.

Version 0.11.3 sends smaller, regular wheel increments for PC control scrolling and clears any partial scroll on release or direction change. The calibration UI now labels trigger values as reported bytes and explains the 0–255 hardware report limit. Main screen and profile copy is shorter. The new scrolling behavior has a pure unit test and still needs a physical desktop retest.

The app reads HID reports, uses Windows audio loopback, and listens for published telemetry. It does not inject code into games. Steam Input or another controller tool may write to the same controller; Diagnostics reports likely conflicts, and Reset releases effects when this app owns them.
