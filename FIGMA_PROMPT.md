# Figma redesign prompt for CONTROLLER

Design a polished, buildable Windows desktop app called **CONTROLLER**, a local DualSense and DualSense Edge workbench. Create desktop frames at 1440 × 900 and a compact 1024 × 768 layout, plus reusable components, color tokens, states, and a short interaction specification. The design should feel like a precise instrument panel: clear hierarchy, comfortable spacing, readable type, strong contrast, restrained motion, and excellent keyboard and controller focus states. Avoid decorative telemetry that does not help the user. Keep advanced protocol data in Diagnostics.

The primary **Input** screen must feature an accurate, front-facing DualSense drawing, not an angled product photo. Treat it as an interactive live map. When a button is pressed, its matching shape lights up; both stick caps move in the same direction and proportion as the real sticks; L2 and R2 visibly travel and show calibrated percentages; one or two touch contacts appear at their actual calibrated positions. Show an activity trace that responds to either stick, buttons, and triggers. Show controller name, USB or Bluetooth status, battery level, charging state, battery history, and an honestly labeled *estimated charge rate* based on coarse battery steps. Remove the ever-increasing Status/packet counter from this main screen.

Make **Game mode** the default, prominent mode. In Game mode, input remains available to games and the app only displays it; button presses do not navigate the app or desktop. **PC control** is opt-in. When CONTROLLER has focus, the pad can navigate pages and controls with visible focus. When another window has focus, one finger on the touchpad moves the desktop pointer, the right stick scrolls up or down, L2 is left click, and R2 is right click. Add a separate **PC controls / Macros** screen where every other button can be assigned a keyboard key, hold, tap, or short key sequence, with adjustable pointer sensitivity, scroll direction, trigger click threshold, and a restore defaults action. Show mode state and an easy route back to Game mode.

Create dedicated screens for **Adaptive triggers**, **Haptics**, **Touch and motion**, **Lightbar**, **Profiles**, **Calibration**, and **Diagnostics**. Trigger editing needs **L2 and R2 zone graphs stacked vertically and visible together**, ten draggable force zones per trigger, resistance/vibration/weapon/bow/off modes, two live pull markers, intensity, and explicit resistance start, break point, and bow snap strength controls. Do not use dense numeric force fields. Include safe preview timing and explain that Bow support can vary by firmware. Haptics needs waveform, shape, frequency, attack/release, strength, left/right balance, tactile presets, a preview action, output route feedback (USB voice coils versus motor fallback), an optional audible PC sketch, and an audio-to-grips bridge with intensity. Touch and motion needs live contacts, touchpad pointer/gestures, gyro aim, and gyro rest calibration.

Lightbar needs a large **front view of the actual DualSense shape**, with the selected RGB LED color shown as soft light through the touchpad seams and nearby white plastic, rather than solid abstract arcs. Show the five separate lower **white player indicators** with their own per-light on/off controls; the RGB picker does not color them. Include several named palettes, a custom hex field and color picker, locally saved favorites, and a clear Apply action. Also show optional battery, screen, sensor, and race telemetry color modes without burying the basic color task. Profiles should save trigger, haptic, gyro, and game remap settings, with import/export and executable matching. Show editable Hanzo, Genji, and Soldier: 76 weapon feel templates; label that live ability and hit effects need game event data. Include a small optional XInput driver setup path for the bundled signed ViGEmBus installer and an optional HidHide download; direct controller features require neither. Calibration should be **untimed and step by step**, like the Switch 2 guide: show moving stick dots and accumulated travel, the controller's reported 0–255 trigger bytes and peaks captured on release, and a touchpad map whose corner markers fill as touched. The user advances each step and saves only when the needed range is captured. Provide Cancel and Reset and report failed saves clearly. State that software cannot infer physical travel after the 8-bit report saturates. Diagnostics should contain raw sensor and report details, device selection, connection issues, tests, and logs.

Provide layouts for disconnected, connected Game mode, connected PC control, calibration in progress, invalid calibration, applying an effect, and output unavailable. Keep the core actions usable with mouse, keyboard, and the controller. Use real labels and realistic sample data; avoid placeholder boxes. Include a component specification for the live controller map and how its parts animate from input values, so developers can implement the design directly.

Use short, direct UI copy. Label what a control does and what happened after it is pressed. Avoid slogans, metaphors, and decorative descriptions.
